iGhostVT 1.6.7 keeps a terminal's screen whole after it reconnects, and keeps connections to devices on the same network off VPNs and proxy apps.

- After coming back to the app, a program like Claude Code could leave stray text on screen — "esc to interrupt" half under "still thinking" — until it next redrew everything. Reconnecting rebuilds the screen from the session's saved output, which starts partway through. Now the program in front is asked to redraw its whole screen every time a terminal reconnects.
- With a VPN or a proxy app such as Surge on, a connection to a device on the same network could go through the proxy instead of straight across the network. It now always uses Wi-Fi or Ethernet. Connections through the relay still go however the system routes them.
- On a network with IPv6, a device connecting by its public IPv6 address was turned away as "not on the local network", even from the same network. The connection then fell back to the relay. That address now counts as local when it is on the same network as this device. This half of the fix is on the host, so update the device you connect to.
- A program started directly with `ighostvt-cli new -- <command>` or a Shortcut ignored ^C, never noticed the window resizing, and took a few extra seconds to close. It now gets those signals like a program started from a shell.

Choose `iphoneos-arm64e` for roothide, `iphoneos-arm64` for a rootless bootstrap, `iGhostVT-1.6.7-macos-notarized.zip` for a Mac — it is signed and notarized, so it opens without clearing quarantine, and updates itself — or `GhostRemote-1.6.7.ipa` for an iPhone or iPad without custom firmware, which your sideloading app signs as it installs it. To run the relay, use the attached `compose.yml`; the image is `ghcr.io/owngoal-dev/ighostvt-relay`, and the digest is in `relay-image.txt`. SHA-256 sums are in `SHA256SUMS`, and the Mac app's in `SHA256SUMS.macos`.
