iGhostVT 1.6.39 opens the MCP server to AI apps on other devices on your local network, and makes its approval page readable in dark mode.

- An AI app could use the MCP server only from the same device. MCP Server (until now Local MCP Server) also accepts apps on other devices on your local network, each still only after you allow it in iGhostVT, and refuses connections from anywhere else. Its address uses the device's `.local` name, such as `http://my-mac.local:18765/mcp`. The connection is not encrypted, so use it only on a network you trust.
- The MCP settings hid the server's address behind Copy Address. On iPhone and iPad the section now shows both addresses — `127.0.0.1` for an app on the same device, the `.local` one for other devices — which you tap to copy, how many apps you have allowed, and Forget All; on a Mac, the button beside MCP Server opens them in a sheet, where you click an address to copy it.
- In dark mode, the approval page an AI app opens showed its title, text, code and Cancel white on white. It is readable in both appearances now, and shows only the app's name, the code and Cancel.

Choose `iphoneos-arm64e` for roothide, `iphoneos-arm64` for a rootless bootstrap, `iGhostVT-1.6.39-macos-notarized.zip` for a Mac — it is signed and notarized, so it opens without clearing quarantine, and updates itself — or `GhostRemote-1.6.39.ipa` for an iPhone or iPad without custom firmware, which your sideloading app signs as it installs it. To run the relay, use the attached `compose.yml`; the image is `ghcr.io/owngoal-dev/ighostvt-relay`, and the digest is in `relay-image.txt`. SHA-256 sums are in `SHA256SUMS`, and the Mac app's in `SHA256SUMS.macos`.
