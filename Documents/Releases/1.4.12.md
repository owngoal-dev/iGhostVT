iGhostVT 1.4.12 lets `ighostvt-cli` manage remote access, adds a script that installs the Mac app with no one at the screen, and stops asking a Mac with nothing paired for Local Network access; it connects to devices on any 1.4 release.

- Remote access could be turned on, paired and given a relay only from Settings. `ighostvt-cli remote` now does the same from a shell: `status`, `on` and `off`, `pair` (prints a pairing code, and with `--wait` stays until a device pairs), `revoke`, `name`, and on a Mac `relay` to use a `.vtrpsc` file as importing it in Settings does. It acts with the rights of the user who runs it; on a Mac, run it as that user, not as root.
- Setting up a Mac took someone at the screen. `Scripts/mac-install.sh`, run with sudo, installs the notarized release after checking its SHA-256 and Gatekeeper's verdict, opens iGhostVT when the user logs in, and with `--relay` and `--pair` sets the relay, turns remote access on and prints a pairing code. macOS gives no way to grant Local Network access from a script: until someone allows it, the Mac works through a relay and takes direct connections, but nearby devices do not find it.
- A Mac with no paired device asked for Local Network access as soon as iGhostVT first opened. It now asks only when there is a device to look for, or when you open Settings ▸ Remote Access to pair.

Choose `iphoneos-arm64e` for roothide, `iphoneos-arm64` for a rootless bootstrap, `iGhostVT-1.4.12-macos-notarized.zip` for a Mac — it is signed and notarized, so it opens without clearing quarantine — or `GhostRemote-1.4.12.ipa` for an iPhone or iPad without custom firmware, which your sideloading app signs as it installs it. To run the relay, use the attached `compose.yml`; the image is `ghcr.io/owngoal-dev/ighostvt-relay`, and the digest is in `relay-image.txt`. SHA-256 sums are in `SHA256SUMS`, and the Mac app's in `SHA256SUMS.macos`.
